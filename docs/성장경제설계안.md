# C단계 설계안 — 성장·경제 (2026-11-26 승인, 확인 필요 항목 결정 반영)

> 규칙: `docs/성장경제규칙.md` 11번 C-1(경제)·C-2(성장). 미션(8번)은 D단계라 제외.
> 수치는 전부 임시이며 데이터(ScriptableObject)에서 조정한다. 텍스트·이미지는 "[미정]"과 회색 도형.
> 시뮬레이션 결과 원본: `docs/밸런스기록.md` "C단계 설계 시뮬레이션".

## 1. 데이터 구조

### 1-1. 새 설정 에셋 1개: `EconomySettings` (성장·경제 수치 한곳)

BattleSettings가 전투 수치 한곳이듯, 성장·경제 수치는 여기 모은다.

| 묶음 | 칸 (임시값) |
|---|---|
| 보상 확률 | 일반 전투 {재료 15%, 고급 5%, 희귀 0%} / 스토리·보스 첫 클리어 {20%, 10%, 3%} / 재도전 골드·경험치 배율 0.3 (확률은 그대로) (결정 6) |
| 드롭 목록 | 재료 아이템(강화석), 고급 장비 목록, 희귀 장비 목록 (드롭되면 목록에서 균등 랜덤) |
| 판매 | 판매가 = 구매가 × 0.5 (아이템별 덮어쓰기 가능) |
| 강화 | 단계 표 5칸: +1 (100G, 강화석 1) / +2 (150G, 1) / +3 (200G, 2) / +4 (300G, 2) / +5 (400G, 3). 성공률 100% |
| 레벨 | 다음 레벨까지 경험치 = 20 + 10 × (현재 레벨 − 1), 최대 레벨 30, 레벨당 스탯 포인트 1 |
| 스탯 효과 | 힘 1 = 공격 +1 / 민첩 1 = 도망 +1%p·치명 +0.5%p / 정신력 1 = 최대 체력 +5·디버프 무시 +1%p(최대 30%) / 지능 1 = 최대 기력 +1·전투 시작 시 괴이 정보 획득 +3%p / 매력 1 = 상점 가격 −1%(최대 20%) |
| 직급 | 목록 (1-6 참고) |
| 주인공 기본 | 공격 3, 방어 6 (+ 시작 장비 일반 무기 +2, 일반 방어구 +4 = B단계 시작값 5/10과 같음), 체력 100, 기력 10, 치명 5%, 주사위 2개×6면 |
| 시작 지급 | 일반 주사위, 일반 방어구(장착 상태), 음식 3개, 골드 0 |

### 1-2. 아이템 `ItemData` 확장 (기존 에셋 유지, 칸 추가)

| 칸 | 설명 |
|---|---|
| type | 소비 / 무기 / 방어구 / **재료(새로)** / 특수 |
| grade | 일반 / 고급 / 희귀 (소비·재료는 무시) |
| price | 구매가. 판매가는 0이면 구매가 × 0.5 |
| 소비 | healHp, healEnergy (기존) |
| 무기 | weaponType(주사위), attackBonus, critBonus, skills(최대 2개 — 일반 0, 고급 1, 희귀 2개가 아니면 콘솔 경고) |
| 방어구 | defenseBonus |
| 강화 성장 | 강화 1단계당 무기 공격 +1, 방어구 방어 +2 (아이템별 칸) |

첫 출시 장비 (임시):

| 아이템 | 수치 | 스킬 | 가격 |
|---|---|---|---|
| 일반 주사위 | 공격 +2 | 없음 | 150 |
| 고급 주사위 | 공격 +7 | 다시 굴리기 | 600 |
| 희귀 주사위 | 공격 +10, 치명 +3%p | 다시 굴리기, 주사위 고정 | 2,000 (히든 상점) |
| 일반 방어구 | 방어 +4 | — | 150 |
| 고급 방어구 | 방어 +14 | — | 600 |
| 희귀 방어구 | 방어 +20 | — | 2,000 (히든 상점) |
| 음식 (기존) | 체력 +30 | — | 30 |
| 에너지 드링크 (새로) | 기력 +5 | — | 40 |
| 강화석 (새로, 재료) | — | — | 판매만 20 |

→ 고급 무기 + 고급 방어구 = 공격 10·방어 20 = B단계 "적정 장비(+5/+10)"와 같음.
→ 시작부터 스킬이 있던 B단계와 달리, 스킬은 **고급 무기부터** 생긴다 (규칙 4번 "일반: 스탯만").

### 1-3. 드롭·보상

- `MonsterData`에 칸 추가: goldMin, goldMax, exp. (임시: 일반 괴이 35~50G·경험치 10, 보스 500G·100, 스토리 괴이 150G·30)
- 별도 드롭 테이블 에셋은 만들지 않고, 전투 종류별 확률(EconomySettings) + 장비 목록으로 처리. 괴이별로 다르게 하고 싶으면 MonsterData에 "드롭 덮어쓰기" 칸을 둔다(비워 두면 기본).
- 계산은 순수 C# `RewardCalculator`(엔진처럼 Random 주입) — 게임·시뮬레이터·테스트 공용.
- 결과 창에 골드·경험치·숙련도·드롭·레벨 업 표시.

### 1-4. 상점 `ShopData` (새 SO, 상점 1곳 = 에셋 1개)

shopId, 상점 이름, 아이콘, 점원 이미지(빈 칸), 종류(일반/특수), 판매 목록 [{아이템, 가격 덮어쓰기(−1 = 기본), 조건}], 판매 탭 여부, 강화 탭 여부.
- 편의점: 음식, 에너지 드링크. 구매만.
- 특수 상점: 일반·고급 장비 4종. 구매·판매·강화.
- **히든 상점 (결정 5)**: 희귀 장비 2종. 특수 상점 안의 상호작용 버튼 "[히든 상점 미정]"에 조건 "매력 5 이상"(hideIfUnmet) → 조건을 채우면 버튼이 보이고 같은 상점 창이 열림. 희귀는 이 상점과 첫 클리어 3% 드롭으로만 얻음.

### 1-5. 강화

- 장비마다 강화 단계(0~5)를 가진다 → 장비는 개수 묶음이 아니라 **한 개씩** 저장 (2번 참고).
- 특수 상점 "강화" 탭: 장비 선택 → 현재/다음 수치, 필요 골드·강화석 → 강화.

### 1-6. 직급·재능

`RankData` 목록(EconomySettings 안, 병원비는 직급별 칸에서 조정 — 결정 1):

| 직급 | 조건 (임시) | 병원비 | 승급 시 재능 후보 |
|---|---|---|---|
| 수습 요원 | 시작 | 10 | (시작 재능 4개 중 1개) |
| 요원 | 레벨 10 **+ 보스 격파** | 100 | 2단계 재능 3개 중 1개 |
| 선임 요원 | 레벨 20 | 1,000 | 3단계 재능 (출시 후, 칸만) |

`TalentData` (새 SO, 재능 1개 = 에셋 1개): talentId, 이름, 설명, 단계, 효과 목록 [{대상, 값}].
효과 대상(공통 enum): 최대 체력, 공격, 치명, 모든 스탯, 강화 골드 %, 상점 가격 %, 드롭 확률 %, 경험치 %, 디버프 무시 %p.

| 단계 | 재능 (임시) | 효과 |
|---|---|---|
| 1 | 튼튼한 육체 | 최대 체력 +20 |
| 1 | 명사수 | 치명 +8%p |
| 1 | 팔방미인 | 스탯 5개 모두 +1 |
| 1 | 손재주 | 강화 골드 −30% |
| 2 | 강철 정신 | 최대 체력 +20, 디버프 무시 +15%p |
| 2 | 행운아 | 드롭 확률 ×1.5 |
| 2 | 노련함 | 경험치 +25% |

### 1-7. 무기 숙련도·특성

`WeaponMasteryData` (새 SO, 무기 유형 1개 = 에셋 1개, 첫 출시는 주사위 1개):
- 공격 1회 = 숙련도 경험치 1, 레벨당 12 (≈ 일반 전투 3번에 1레벨 → 1시간에 9레벨 안팎)
- 레벨마다 치명 +0.5%p, 5레벨마다 공격 +1
- 10레벨마다 특성 2개 중 1개: `TraitData` (새 SO) [{10레벨: 주사위 +1개 / 주사위 면 +2}, {20레벨: 조합 배수 +50% / 치명타 시 주사위 1개 더 굴려 합에 더함}, 30레벨 이후는 칸만]
- 특성은 그 무기 유형을 장착했을 때만 적용.

### 1-8. 스탯 훈련 장소

장소 상호작용 종류에 `Train` 추가, 칸은 `TrainingData` (상호작용 안에 둠):
- 올릴 스탯, 기본 비용 80, 증가분 40 (그 스탯을 훈련한 횟수마다), 성공 시 +1
- 미니게임: 게이지 0~100, 클릭 1번 +7, 초당 −12 감소, 제한 4초, 목표 구간 65~85, 100을 넘으면 즉시 실패. 훈련할수록 목표 구간이 1씩 좁아짐(최소 폭 8)
- 실패해도 비용은 나감 (임시)
- 판정 로직은 순수 C# `TrainingGauge` (테스트 가능하게)

## 2. PlayerState 확장 (E단계 JSON 저장 호환)

JsonUtility가 그대로 저장할 수 있게 **List·기본형·[Serializable] 클래스만** 쓴다 (Dictionary 금지).

```
// 성장
int level = 1, exp = 0, statPoints = 0;
StatBlock stats;            // 힘·민첩·정신력·지능·매력 (레벨 포인트 + 훈련 + 재능 제외 순수 투자분)
StatBlock trainCount;       // 스탯별 훈련 횟수 (비용 계산용)
string rankId = "trainee";
List<string> talentIds;
int pendingTalentPicks;     // 승급 후 아직 안 고른 재능 수
List<MasteryState> masteries;   // {weaponType, level, exp, List<string> traitIds, pendingTraitPicks}

// 장비 (한 개씩)
List<OwnedEquipment> equipment; // {uid, itemId, enhance}
int nextEquipUid = 1;
int equippedWeaponUid, equippedArmorUid;   // 0 = 없음

// 기존 유지: currentHp, currentEnergy, gold, items(소비·재료 묶음), respawnAreaId/PlaceId
```

- 기존 `weaponId`·`armorId`(아직 안 씀)는 위 uid 방식으로 교체. 세이브 파일이 아직 없어서 호환 문제 없음.
- **계산된 수치**(maxHp, maxEnergy, attack, defense, critChance, agility, diceCount, diceFaces, skillIds, 디버프 무시, 조합 보너스)는 `PlayerStats.Recalculate(player)` 한 함수가 기본값 + 스탯 + 장비 + 강화 + 재능 + 숙련도·특성으로 다시 채운다. 장착·레벨 업·훈련·재능 선택 때마다 호출.
  - 장점: BattleEngine은 지금처럼 player.attack 등을 읽으면 되므로 전투 코드 변경이 작다. 엔진의 EquipAttack/EquipDefense(무기 ID로 더하기)는 제거(중복 방지).
  - 저장에는 계산값도 들어가지만, 불러온 뒤 Recalculate로 다시 맞춘다.
- JSON 왕복 테스트를 EditMode 테스트에 추가.

전투 엔진 변경은 3곳만: 디버프 무시(정신력), 전투 시작 정보 획득(지능), 특성 2개(조합 배수 보너스, 치명타 추가 굴림).

## 3. 새 장소 (전부 이름·설명·이미지 "[미정]")

| 장소 | 구역 | 유형 | 상호작용 |
|---|---|---|---|
| 병원 | 도심 | 안전 | 치료 (들어가면 자동으로 복귀 지점) |
| 편의점 (기존 safe 전환) | 도심 | 안전 | 상점(편의점) + 기존 점원 대화 유지 |
| 특수 상점 | 도심 | 특별 | 상점(특수: 구매·판매·강화) + 히든 상점(매력 5) |
| 헬스장 (힘) | 도심 | 일반 | 훈련 |
| 도서관 (지능) | 도심 | 일반 | 훈련 |
| 카페 (매력) | 도심 | 일반 | 훈련 |
| 강변 공원 (민첩) | 강 | 일반 | 훈련 |
| 산사 명상터 (정신력) | 산 | 일반 | 훈련 |

- `InteractionType`에 Shop·Hospital·Train 추가. 장소 안에서 버튼을 누르면 해당 창이 열린다 (기존 Talk/Investigate와 같은 방식).
- A단계 시험 장소 정리 (결정 7): safe → 편의점으로 전환(locationId "safe" 유지, 이름 "[편의점 미정]", 점원 대화 그대로 → 대화 기능 테스트 유지). normal·special·danger는 도심 장소 목록에서 빼고 에셋 삭제. danger를 패배 복귀 기본값으로 쓰던 곳은 병원으로 교체.
- 도심 마커 수: 기존 alley + 편의점 + 새 5곳(병원·특수 상점·헬스장·도서관·카페) = 7곳.

## 4. 화면

모두 코드 빌더(전투 화면처럼 `UIBuilder` 메뉴)로 만들어 다시 생성 가능하게 한다.

| 화면 | 구성 |
|---|---|
| **상단 바** (지도 공통, 맵 구상도 "공통 상단") | 오른쪽 위 골드 표시 + 프로필 버튼. 레벨 업·재능·특성 대기 시 프로필에 빨간 점. 전투 화면의 기존 프로필 자리도 같은 창을 연다 |
| **상점 창** (맵 구상도 "일반 상점 구매 창") | 왼쪽 점원 이미지 자리, 오른쪽 위 상점 아이콘·이름, 탭 [구매][판매][강화] (특수 상점만 판매·강화), 상품 행 4개 = 이미지·이름·효과와 소지 개수·가격+구매 버튼, ▲▼ 페이지, 나가기. 매력 할인 시 원가에 줄 긋고 할인가. 장비는 구매 확인 팝업 |
| 판매 탭 | 장비·재료 목록, 판매가, 판매 버튼. 장착 중인 장비는 판매 불가 표시 |
| 강화 탭 | 왼쪽 장비 목록, 오른쪽 "+2 → +3, 공격 9 → 10, 필요 200G·강화석 2 (보유 3)", 강화 버튼 |
| **병원 창** | 점원 자리, 체력·기력 막대, "전체 치료 (100G)" 버튼, 결과 문구 "[대사 미정]", "이 병원이 복귀 지점이 되었다" 안내 |
| **홈·스탯 창** (프로필) | 전체 화면 팝업, 탭 5개: 스탯(5개 + 남은 포인트 + 찍기 버튼, 계산된 수치 표) / 장비(무기·방어구 칸, 목록에서 장착) / 인벤토리(소비 아이템 사용, 재료 보기) / 숙련도(레벨·경험치 막대·고른 특성) / 직급·재능. 전투 중에는 **보기만** (장착·사용 불가) |
| **재능 선택** | 제목 "나는 어떤 재능이 있을까?", 카드 4장(이름·설명), 고르면 확인. 승급 때는 같은 창에 2단계 카드 3장 |
| **특성 선택** | 숙련도 10레벨 도달 시 전투 결과 창 뒤에 카드 2장 중 1개 |
| **훈련 미니게임** | 가로 게이지 막대, 초록 목표 구간, 빨간 임계선, 남은 시간, "연타!" 안내, 화면 어디든 클릭, 결과(성공 +1 / 실패). 시작 전 비용·현재 스탯 표시 |
| 결과 창 (기존 확장) | 골드·경험치·숙련도·드롭 목록·"레벨 업!"·"첫 클리어" |

## 5. 게임 시작 흐름 (규칙 9번)

```
새 게임 → 시작 만화(Comic_Opening, 빈 칸 4개) → 재능 선택 → 지역 맵
  → 도심만 열림 → 도심 구역: 병원만 열림 → 병원 들어감
  → 플래그 intro:hospital + 복귀 지점 등록 + 안내 "[대사 미정]" → 모든 장소 열림
```

- 잠긴 마커: 회색 + 자물쇠 표시. 누르면 정보창에 "[아직 갈 수 없다]", 진입 버튼 꺼짐.
- 잠금은 장소마다 조건을 다는 대신 **시작 규칙 1개**로 처리: EconomySettings에 "시작 병원" 칸 → 플래그가 없으면 시작 병원과 그 구역만 열림. (장소별 숨김·잠금은 6번 조건 구조로 따로 가능)
- 테스트·개발용: 메뉴 "요원 > (개발) 시작 흐름 건너뛰기".
- 패배 복귀 기본값 = 시작 병원 (지금 BattleSettings 기본 복귀 장소를 병원으로 교체).

## 6. 매력 등 범용 조건

```
[Serializable] Condition   { kind, stat, value, key }
   kind: 스탯 이상 / 레벨 이상 / 직급 이상 / 플래그 있음 / 플래그 없음 / 아이템 보유 / 재능 보유
[Serializable] ConditionSet { List<Condition> all (모두 만족), bool hideIfUnmet, string lockedText }
static ConditionChecker.Check(GameState, ConditionSet) → bool
```

붙이는 곳: 대화 선택지(TalkChoice), 장소 상호작용(PlaceInteraction), 장소(AreaData의 장소 항목), 상점 품목(ShopEntry), 직급 조건(RankData).
- hideIfUnmet = 켜면 안 보임(히든 선택지·히든 장소), 끄면 잠긴 채 보임 + "[매력 5 필요]".
- 조건을 만족한 매력 선택지는 앞에 "[매력]" 표시 (임시).
- 히든 내용은 비워 두고, 테스트용으로 매력 3 선택지 1개·매력 5 품목 1개만 넣는다.
